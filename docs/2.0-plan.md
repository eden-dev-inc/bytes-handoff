# 2.0.0 plan

- Fix the confirmed 1.3.1 write-budget leak with a RAII charge that follows every accepted request from submission through completion or teardown. Cover cancellation at byte-budget and channel waits, writer abort/panic, I/O failure, callback panic, dropped tickets, and close/drain behavior without changing existing stream APIs.
- Add a synchronous, runtime-free generic message queue: `MessageHandoff::<T>::new(config)` returns sender/receiver; sender `try_send(value, byte_len)` returns the owned value on rejection; receiver `try_recv()` returns a cloneable `TrackedMessage<T>`. Item and declared-byte charges survive queueing, active use, and wrapper clones until final drop. Close rejects admissions while accepted messages remain drainable; the last receiver drop discards queued messages. Validate positive limits and count zero-byte messages as items.
- Feature-gate current stream frontends and their dependencies behind default-on `tokio`, preserving current default and explicitly enabled optional-feature behavior. Keep `--no-default-features` free of Tokio and other stream/runtime dependencies. Because 1.3.x exposed stream APIs without defaults, document that 2.0 users need to enable `tokio` explicitly to retain them.
- Bump to 2.0.0, document the message API, migration path, and logical accounting limits, add an example, and extend CI for tests, MSRV, and feature combinations. The earlier 1.4.0 candidate was unpublished and superseded by the major version. No private adapter or transport details enter this crate.
- Validate deterministic cancellation, error and teardown paths; concurrent active-retention and clones, receiver teardown, dropped values, invalid/zero limits, and lifecycle races; run formatting, Clippy, tests, doctests, examples, no-default and all-features checks.
